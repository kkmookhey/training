## The other two doors: data and fine-tuning

The artifact is the door we'll pick today. There are two more, and they're harder to detect.

| Door | What the attacker controls | Why it's worse than a bad `.pkl` |
|---|---|---|
| **Dataset poisoning** | a fraction of the training corpus — often **scraped from the open web** | no file to hash. The payload is *statistical*, distributed across weights. |
| **Malicious fine-tuning** | a LoRA / adapter / "community-tuned" checkpoint | inherits the base model's reputation. Safety alignment can be **stripped in a few hundred steps**. |

**Carlini et al.** showed web-scale corpora are poisonable for **~$60** — buy the expired domains behind a small % of the URLs and serve what you like.

<!-- Notes: The honest caveat this module needs: what we do in the lab is the tractable version. Hash-pinning catches a swapped file; it does nothing about a base model that was already poisoned before you downloaded it. Note the asymmetry that makes fine-tuning attacks attractive: alignment is a thin layer, cheap to remove, and the resulting model still benchmarks well. Detection is an open research problem — say so rather than implying we have an answer. -->

## Backdoors survive the things you'd expect to kill them

A poisoned model isn't a file you scan — it's a behaviour that only appears on a **trigger**.

- Clean on every benchmark. Clean on your eval set. **Clean until the trigger token appears.**
- **Sleeper Agents** (Anthropic, 2024): backdoored behaviour **survived** supervised fine-tuning, RLHF, and adversarial training — and the largest models hid it best.
- Safety training taught the model to *recognise* the trigger, not to *stop obeying* it.

**Provenance beats inspection.** You cannot test a backdoor out of a model you didn't train.

<!-- Notes: The uncomfortable finding and the strongest argument in this module for supply-chain controls over behavioural testing. If your defence is "we evaluate the model before deploying," this is the paper that says your evaluation is exactly what the backdoor was trained to pass. Ties directly to M8: guardrails and evals both measure behaviour, and behaviour is what a trigger-conditioned backdoor controls. -->

## What a pickle actually is

Python's built-in object serialization. Critically: **it stores a program, not just data.**

Unpickling **executes** — the format includes opcodes that import and call functions.

```python
class _Poisoned:
    def __reduce__(self):
        return (os.system, ("echo eiger-m4-rce",))

out.write_bytes(pickle.dumps(_Poisoned(), protocol=4))   # → community_model.pkl
```

<!-- Notes: The mechanism, said carefully. __reduce__ is a legitimate, documented protocol: it lets an object tell the unpickler "to rebuild me, call this function with these arguments." The unpickler dutifully does. So a pickle isn't a description of an object, it's instructions for reconstructing one — and "call os.system" is a perfectly valid instruction. Note protocol=4 is why this shows up as STACK_GLOBAL + REDUCE rather than a plain GLOBAL in the bytecode. -->

---

## Merely loading it is game over

```python
pickle.load(f)      # → __reduce__ fires → os.system(...) runs
```

No inference. No prompt. No model ever executed. **The file loaded — that was enough.**

In a real attack that `echo` is a reverse shell.

<!-- Notes: Land the asymmetry. Every other module needed the model to cooperate; this one needs nothing but a file read. Our payload is an echo so the demo is safe, but the mechanism is identical to a reverse shell — nullifAI's real-world version was exactly that, connecting to a hard-coded IP. The mechanism is the point, not the payload. -->

## Pickle is everywhere in ML

| Format | Pickle under the hood? |
|---|---|
| `.pkl`, `.pickle` | yes — obviously |
| `.pt`, `.pth` (PyTorch) | **yes** — `torch.save` used pickle |
| `joblib` (scikit-learn) | **yes** |
| `.npy` with `allow_pickle=True` | **yes** |
| `.safetensors` | **no** — by design |

<!-- Notes: This table is the single most practically useful thing a participant leaves M4 with. The PyTorch row is the one that surprises people — the default checkpoint format in the most popular deep-learning framework was pickle-based, which is why torch.load grew a weights_only flag. If they remember one slide from this module, it should be this one. -->

## Where Eiger would trip it

```python
def load_artifact(path, settings):
    if settings.sec_artifact_verification:                  # SECURE
        if Path(path).suffix != ".safetensors":
            raise ArtifactError("refused: only .safetensors permitted")
        if sha256_file(path) not in ALLOWED_HASHES:
            raise ArtifactError("refused: not in pinned allowlist")
        return Path(path).read_bytes()                      # never unpickles
    with open(path, "rb") as f:                             # VULNERABLE
        return pickle.load(f)                               # → RCE
```

<!-- Notes: Two guards in the secure branch, in the right order: format allowlist first, then hash pinning. Either alone is weaker — format-only lets a poisoned safetensors-named file through if you trust extensions, hash-only still unpickles. Also note the secure branch never calls pickle at all; it's not a safer unpickle, it's no unpickle. -->

## Scoping: you prove it without running it

`SEC_ARTIFACT_VERIFICATION` gates **only** `load_artifact` — the one code path that actually unpickles.

**You never load the file.** You prove the finding **statically**, from the bytecode, and submit it.

> Detonating malware on shared infrastructure to prove it is malware is not an audit. It's an incident.

## The scanner: read the bytecode, never execute it

`halcyon.scan_artifact` walks the pickle with `pickletools.genops` — **it never unpickles.**

It flags three danger classes:

| Signal | Meaning |
|---|---|
| `GLOBAL` / `STACK_GLOBAL` → `os`, `subprocess`, `sys`, `posix`… | importing something dangerous |
| `REDUCE` | the opcode that actually **calls** |

<!-- Notes: The important design property: static disassembly, not execution. genops walks opcodes and yields them; nothing is reconstructed, so scanning a malicious pickle is safe. That distinction — parse vs execute — is the same one that makes safetensors safe, and it's a transferable principle for any deserialization audit. -->

## Why safetensors is safe — structurally

A safetensors file is **a JSON header of shapes and dtypes, plus raw tensor bytes.**

No callable. No import. **No code path.** Loading it cannot execute anything.

That is the entire reason the format exists.

<!-- Notes: Contrast with pickle explicitly: pickle is a program, safetensors is data. There's no opcode to abuse because there are no opcodes. This is a rare case in security where a clean structural fix exists and is already widely adopted — so "use safetensors" is genuinely actionable advice rather than a hope. -->

## Secure it: the loader diff (demo, not graded)

| Vulnerable | Secure |
|---|---|
| any file → `pickle.load()` | **format allowlist**: `.safetensors` only |
| `__reduce__` fires → `os.system` | **then** sha256 must be in a pinned allowlist |
| RCE from "loading a model" | refused before a byte is deserialized |

<!-- Notes: M4's secure beat is a demo rather than a /validate flip, because the graded path is a known-answer check with no flag to toggle. Walk the two-guard order again and note the phrase "before a byte is deserialized" — the refusal happens on metadata, not on content, which is what makes it safe. -->

## Now break the fix

- **rename it** — does anything trust the *extension* rather than the *content*?
- **the allowlist is empty by default** (`ALLOWED_HASHES: set[str] = set()`) — who populates it, and how do they verify a hash is legitimate?
- **TOCTOU** — hash checked, then the file re-read from disk
- **attack a different link** — the tokenizer, config, remote code (`trust_remote_code=True`), or a `pip` dependency instead of the weights

<!-- Notes: The discussion beat, and the second bullet is the sharp one — hash pinning moves the trust problem rather than solving it. Somebody has to decide the first hash is trustworthy, and that decision is usually "it's what we downloaded on Tuesday." Also raise trust_remote_code=True, which is the modern equivalent of unpickling: a Hugging Face flag that executes arbitrary repo code on load, widely pasted from tutorials. -->

## What actually holds

| Defence | Strength |
|---|---|
| **Prefer safe formats** (safetensors) | **strong** — removes the capability |
| **Hash-pin + verify** artifacts | **strong** — if you trust the first hash |
| **Static scanning** before load (`picklescan`, `modelscan`) | moderate — nullifAI evaded exactly this |
| Lockfile CVE audit in CI | **strong** for the dependency half |
| "We only download from reputable hubs" | none — the hubs are the delivery channel |

<!-- Notes: The scorecard. Note that scanning is only moderate, and be specific about why: nullifAI beat platform-side PickleScan by breaking the stream. Scanners are a useful layer and a losing arms race. Choosing a format with no code-execution semantics is the structural fix — same lesson as every other module, just applied to file formats. -->

## The lesson to name

# Your model is a dependency.

Treat weights, tokenizers and configs exactly like third-party code: pin them, verify them, scan them, and **prefer formats that cannot execute.**

<!-- Notes: The reframing that changes behaviour. Nobody would `curl | sudo bash` a random script, and everyone does the moral equivalent with model weights daily. Once "model = dependency" lands, existing supply-chain instincts transfer wholesale: SBOMs, pinning, provenance, scanning, least privilege on the loading process. -->

## Take this back to work on Monday

- Inventory your model artifacts. **Which are pickle-based?** (`.pt`/`.pth` count.)
- Migrate to **safetensors** wherever the framework supports it
- Hash-pin weights; verify on load — `torch.load(..., weights_only=True)`
- Scan artifacts on ingest (`picklescan` / `modelscan`) — knowing it's evadable
- Grep for **`trust_remote_code=True`** and justify every hit
- Audit your lockfile against a CVE database **in CI**

<!-- Notes: Six actions, and the weights_only=True tip is the highest-value one-liner — it's a single kwarg that removes the entire pickle-RCE class from PyTorch loading, and most teams don't know it exists. The trust_remote_code grep usually finds something. -->
