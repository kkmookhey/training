## Two days. One target. Three verbs.

**Build → Break → Secure**, every module.

<!-- Notes: This is the rhythm for all 8 modules. You'll stand up a vulnerable layer, exploit it, then flip a single security flag and watch the exploit die. The diff between vulnerable and secure IS the lesson. -->

---

## AI isn't one thing you attack.

It's a **supply chain**.

<!-- Notes: The core reframe. People come in thinking "prompt injection" is the topic. It's one attack on one layer. Real systems are a chain of components, each trusting the last, each adding attack surface. We attack the chain, in order. -->

---

## The spine

```
chatbot → RAG → agent → MCP → multi-agent → production
```

Each layer adds attack surface. The OWASP LLM Top 10 lands where it lives.

<!-- Notes: Draw this as a horizontal stack building left to right. This is the map for the entire course, and it uses the SAME six words as the Iggy table on the next slide — one map, not two. We are NOT teaching OWASP as a checklist — we walk the chain and the vulnerabilities appear where they actually occur. Mirrors a real engagement. -->

## Meet the target: **Eiger**

An AI-first **neobank**. Its assistant is **Iggy**.

Money movement + PII = real stakes on every lab.

<!-- Notes: One company for two days. You pwn Eiger end to end. Because it's a bank, every exploit has concrete impact — leak a secret, move money, approve a fraudulent dispute. Not abstract. -->

## Iggy grows teeth each module

| Layer | What's new | Module |
|-------|-----------|--------|
| L0 chatbot | direct injection | M1 |
| L1 RAG | indirect injection | M3 |
| L2 agent | tool abuse | M5 |
| L3 MCP | tool poisoning | M6 |
| L4 multi-agent | cascading trust | M7 |
| L5 production | bypass + defend | M8 |

*M2 (output handling) rides on L0/L1; M4 (supply-chain poisoning) targets the L1 data/model — same layers, new attacks.*

## How you know you won

Pass/fail is a **server-side audit log** —
not what the model *said*.

<!-- Notes: Critical, and reassuring. LLMs are non-deterministic; we never grade on the model's words. Every objective is validated by a mechanism query: did the exploit actually fire? This is why the labs are reliable and repeatable. You'll see /validate return core: pass. -->

---

## Rules of the range

- **One build, one flag.** `vulnerable` ↔ `secure`.
- **Reset** any module, any time.
- **Core** objective for everyone · **stretch** for fast finishers.

<!-- Notes: No difficulty ladder — a floor and a ceiling. If you break something, reset. If you finish early, there's always a stretch. Day 1 is keyless (a shared model we host); Day 2 uses your own API key. Both days run in your browser against our hosted target — nothing to install but Burp. (Aside for Day 2: the flag model is granular under the hood — a couple of modules flip more than one — but vulnerable↔secure is the mental model.) -->

## The attacker mindset

You're not "prompting."
You're supplying **untrusted input that becomes instructions.**

<!-- Notes: The one idea to carry all week. Every layer we attack has a boundary where data crosses into instruction — the prompt, a retrieved doc, a tool description, another agent's message. Find that boundary, own the system. -->
