## Two days. One target. Three verbs.

**Build → Break → Secure**, every module.

<!-- Notes: This is the rhythm for all eight modules. You stand up a vulnerable layer, you exploit it, then you flip a single security flag and watch the exploit die. The diff between vulnerable and secure is the lesson. -->

---

## AI isn't one thing you attack.

It's a **supply chain**.

<!-- Notes: Most people walk in thinking prompt injection is the topic. It's one attack on one layer. Real systems are a chain of components — each one trusting the last, each one adding attack surface. We're going to attack that chain, in order. -->

---

## The spine

```
chatbot → RAG → agent → MCP → multi-agent → production
```

Each layer adds attack surface. The OWASP LLM Top 10 lands where it lives.

<!-- Notes: This is the map for the whole course — a stack that builds left to right. It uses the same six words as the Eiger table you'll see next; it's one map, not two. We're not teaching OWASP as a checklist. We walk the chain, and the vulnerabilities show up where they actually occur — the way they would in a real engagement. -->

---

## Meet the target: **Eiger**

An AI-first **neobank**. Its assistant is **Iggy**.

Money movement + PII = real stakes on every lab.

<!-- Notes: One company for two days — you pwn Eiger end to end. And because it's a bank, every exploit has concrete impact: you leak a secret, you move money, you approve a fraudulent dispute. Nothing abstract. -->

## Iggy grows teeth each module

| Layer | What's new | Module |
|-------|-----------|--------|
| L0 chatbot | direct injection | M1 |
| L1 RAG | indirect injection | M3 |
| L2 agent | tool abuse | M5 |
| L3 MCP | tool poisoning | M6 |
| L4 multi-agent | cascading trust | M7 |
| L5 production | bypass + defend | M8 |

*M2 (output handling) rides on L0/L1; M4 (supply-chain poisoning) targets the L1 data/model — same layers, new attacks.*

<!-- Notes: Same assistant, more surface each time — and these layer names match the map you just saw exactly. By the end you'll have lived every row in this table. Two of the modules don't add a new layer: M2 attacks the chatbot and RAG output path, and M4 attacks the data and model feeding the RAG layer. Don't worry about memorizing it now — it's a preview. -->

## How you know you won

Pass/fail is a **server-side audit log** —
not what the model *said*.

<!-- Notes: This one's important, and it's reassuring: LLMs are non-deterministic, so we never grade on the model's words. Every objective is validated by a mechanism query — did the exploit actually fire? That's why these labs are reliable and repeatable. You'll see /validate come back with core: pass. -->

---

## Rules of the range

- **One build, one flag.** `vulnerable` ↔ `secure`.
- **Reset** any module, any time.
- **Core** objective for everyone · **stretch** for fast finishers.

<!-- Notes: There's no difficulty ladder here — just a floor and a ceiling. Break something, reset. Finish early, there's always a stretch. Day 1 is keyless on a model we host; Day 2 you use your own key. Both days run in your browser against our hosted target — nothing to install but Burp. -->

## The attacker mindset

You're not "prompting."
You're supplying **untrusted input that becomes instructions.**

<!-- Notes: If you carry one idea out of this week, make it this: every layer we attack has a boundary where data crosses into instruction — the prompt, a retrieved doc, a tool description, another agent's message. Find that boundary, and you own the system. -->
